# IDE and terminal guide

[Overview](../README.md) · [LLE browser manual](LLE-manual.md)

Use this guide from a complete compatible checkout. Canonical English and translation CSVs can be edited directly in an IDE, or through `editor_cli.py`, which calls the same `Editor` and `DraftStore` services as the browser. Commands below run from the repository root; they work with Python 3.13 or newer. CI uses Python 3.13.

## Prepare and open the editor

The editor/generators use the standard library, including SQLite. Encrypted snapshot operations additionally require `cryptography`:

```sh
python -m pip install "cryptography>=45,<47"
python -B localization/tools/manage.py prepare
python -B localization/tools/editor_server.py
```

`localization/start_editor.cmd` is available on Windows. Add `--no-browser` to `editor_server.py` to start without opening a tab. The service binds to `127.0.0.1`; stop with Ctrl+C or Settings → Quit editor.

IDE commands operate on the checkout containing the scripts, independently of a portable editor's selected source project. Close an LLE session running from this same checkout before using `editor_cli.py`. The CLI leaves browser preferences unchanged. Put the explicit `--game-folder` option **before** its subcommand for Game/All writes.

## Workflow and canonical files


Canonical sources are ordinary XML and UTF-8 CSV files. IDE commands operate on their own checkout, independently of a portable editor's selected source connection.

| Operation | IDE/terminal workflow |
| --- | --- |
| English text, key creation and structural migration | Edit `en_US/primary.xml` and required gameplay references; prepare/check. |
| Translations and grammar/notes | Edit `translations/<locale>.csv`, or use `editor_cli.py draft`. |
| Local drafts, Save versions, Undo/Redo and Apply | `editor_cli.py`, using LLE's `Editor` service and `DraftStore`. |
| Intentional formatting differences | `editor_cli.py accept-formatting` for drafts; `accept-project-formatting` for directly edited CSVs. |
| English and translation handoffs | `merge_localization.py` preview/apply/export, or `editor_cli.py export` including local drafts. |
| Vanilla reference | `snapshot_cloud.py fetch`, or verify/import a prepared snapshot. |
| Release comparisons and translation transfer | `sync_lekmod_versions.py`. |
| Generated localization and validation | `manage.py prepare` and `manage.py check`. |
| Game-only/All Apply | `editor_cli.py --game-folder <path> apply --target game/all`. |
| Read-only game diagnostics | `manage.py diagnose-game --game-folder <path>`. |
| Application-file recovery | `repair_editor.py --editor-root <application-folder>`. |

### Edit canonical sources

Edit English in `localization/en_US/primary.xml`, not the generated English block in game XML. Translation CSV columns are:

```text
key,source_fingerprint,text,gender,plurality,translator_note,updated_at,formatting_approval
```

Legacy six/seven-column CSVs without optional trailing metadata remain readable. Use CSV quoting for commas, quotes and multiline text. `source_fingerprint` pins a translation to reviewed English key/text/grammar. Obtain it from prepared editor rows or `editor_cli.py rows`; do not invent it or refresh stale fingerprints without reviewing the changed English. `updated_at` is an ISO timestamp. `formatting_approval` is normally blank and is generated by explicit review when needed.

```sh
python -B localization/tools/manage.py prepare
# Edit primary.xml, gameplay references and/or translation CSVs.
python -B localization/tools/manage.py prepare
python -B localization/tools/manage.py check
git diff --check
git diff -- localization/en_US localization/translations LEKMOD/Override/CIV5Units_Mongol.xml
```

## Use the shared local workflow

`editor_cli.py --help` lists actions; `editor_cli.py <action> --help` gives options. JSON goes to stdout and preparation/progress/errors to stderr. Local operations share the browser's revisions, source checks, Save versions and history. They do not write Project/Game until Apply.

### Translate, save and apply

1. Read current rows and inspect `lekmod_en_US`, tokens, status and fingerprint.
2. Put the exact UTF-8 translation in `translation.txt`. `--text-file` reads it without adding/removing text; preserve any final newline you intend.
3. Create/update the local draft, Save if you want a restore point, then Apply.
4. Read returned counts and `issues`; independent valid drafts may have applied while rejected rows remain local.

```sh
python -B localization/tools/editor_cli.py rows --locale RU_RU --search TXT_KEY_BUILDING_POLICE_STATION_HELP
python -B localization/tools/editor_cli.py draft --locale RU_RU --key TXT_KEY_BUILDING_POLICE_STATION_HELP --text-file translation.txt
python -B localization/tools/editor_cli.py save
python -B localization/tools/editor_cli.py apply --target project
python -B localization/tools/editor_cli.py issues
```

For grammar/notes, add `--gender`, `--plurality` and/or `--note` to `draft`. Omitting a field keeps its current value; passing an empty value clears it. `draft --locale RU_RU --key <key> --remove` drafts removal of a saved translation override. Apply writes the reviewed removal and restores fallback behavior.

### English creation, editing and structural changes

Without `--locale`, `draft` edits English. New keys use `--create`; `--identifier` requests a permitted rename and `--remove` requests a permitted removal.

```sh
python -B localization/tools/editor_cli.py draft --key TXT_KEY_MY_NEW_DESCRIPTION --create --text "A description for a new gameplay entity."
python -B localization/tools/editor_cli.py apply --target project
python -B localization/tools/editor_cli.py draft --key TXT_KEY_MY_NEW_DESCRIPTION --text-file english.txt
python -B localization/tools/editor_cli.py save
```

`--index` disambiguates repeated English operations. Pending renamed rows can still be selected by their original key. Referenced/translated keys require a structural IDE migration: update gameplay XML/SQL/Lua and translations together, then prepare/check. Creating a text key alone adds no gameplay entity.

English changes alter fingerprints. Review dependent translations; do not refresh their fingerprints mechanically. Matching English and translation drafts can Apply together.

### Save versions, history and backups

| Action | Purpose |
| --- | --- |
| `status` | Pending count, history availability and latest Save status. |
| `drafts` | All pending entries with slots, revisions, source/base and current edit. |
| `save` | Record all local work as an explicit Save (latest 50 retained). |
| `saves` / `load <save_id>` | List and load an exact saved version. |
| `restore` | Restore the latest explicit Save. |
| `undo` / `redo` | Replay local history across rows/languages/modes (up to 100 actions). |
| `backup --output <file>` | Preserve incomplete drafts as JSON. |
| `discard --slot <slot> --revision <revision>` | Remove exactly the reviewed local draft. |

```sh
python -B localization/tools/editor_cli.py status
python -B localization/tools/editor_cli.py drafts
python -B localization/tools/editor_cli.py saves
python -B localization/tools/editor_cli.py load 1
python -B localization/tools/editor_cli.py undo
python -B localization/tools/editor_cli.py redo
python -B localization/tools/editor_cli.py backup --output local-drafts.json
```

Use an ID actually returned by `saves`; `1` above is only an example. Loading/restoring replaces local work and clears Undo/Redo. Save current work first if you need to keep it. Destination files only change on Apply. Backup/export commands require a new output path and do not overwrite an existing file. Draft backup is recovery data, not a validated handoff ZIP.

### Review a changed project baseline

When the same row changed in Project, `review --slot <slot>` returns current English/project text, the exact baseline and draft revision. Review these alongside your draft and save the JSON as **UTF-8**, then rebase:

```sh
python -B localization/tools/editor_cli.py review --slot T:RU_RU:TXT_KEY_BUILDING_POLICE_STATION_HELP
python -B localization/tools/editor_cli.py rebase --review-file reviewed-baseline.json
```

In PowerShell, save the review with `| Set-Content -Encoding utf8 reviewed-baseline.json`. In Bash, `> reviewed-baseline.json` preserves UTF-8 stdout. Rebase checks the returned revision/baseline rather than accepting a newer unseen source. Re-read the row and Apply after review. A missing/conflicted source needs an IDE migration rather than blind rebase.

### Apply and inspect Game

```sh
python -B localization/tools/editor_cli.py --game-folder "C:\Games\Steam\steamapps\common\Sid Meier's Civilization V" apply --target game
python -B localization/tools/editor_cli.py --game-folder "C:\Games\Steam\steamapps\common\Sid Meier's Civilization V" apply --target all
python -B localization/tools/manage.py diagnose-game --game-folder "C:\Games\Steam\steamapps\common\Sid Meier's Civilization V"
```

Game/All require one matching installed Lekmod copy and a closed Civilization V process. Game-only Apply builds the working version without updating canonical Project inputs; All applies Project first, then Game. Installed XML is backed up. A late Game error can leave Project already updated; inspect each destination's status. Diagnostics read localization/cache without deleting the cache. The game engine itself must be tested separately.

## Review intentional formatting

Ordinary rows preserve source token counts; additional icons are allowed and footnotes/bracketed prose are excluded. Intentional differences need an explicit source/text-bound acceptance, shared by CLI, browser, generator, handoffs and CI.

### A pending local draft

After Apply, run `issues` and inspect the reason, current English and draft text. Take `slot`, `current_revision` and `source_fingerprint` from that exact issue:

```sh
python -B localization/tools/editor_cli.py issues
python -B localization/tools/editor_cli.py accept-formatting --slot T:RU_RU:TXT_KEY_BUILDING_POLICE_STATION_HELP --revision <current_revision> --source-fingerprint <source_fingerprint>
python -B localization/tools/editor_cli.py apply --target project
```

Replace placeholders with the returned values. Acceptance saves a local review action and leaves destination writes for Apply. A concurrent draft/source change requires a new review. Other blockers still apply. Missing dynamic substitutions no longer display their values.

### A directly edited canonical CSV

If you deliberately edited a CSV to have different formatting, accept it **before** preparation; the generator otherwise rejects the mismatch:

```sh
python -B localization/tools/editor_cli.py accept-project-formatting --locale RU_RU --key TXT_KEY_BUILDING_POLICE_STATION_HELP
python -B localization/tools/manage.py prepare
python -B localization/tools/manage.py check
```

This backs up the CSV privately, verifies current source and text, and writes the optional `formatting_approval` digest. It refuses stale fingerprints/placeholders and installs nothing in Game. Leave this field blank for normal rows; do not manually copy a digest to another text/source. Text or English changes invalidate acceptance. Notes/grammar-only edits can retain it when the exact text/source remain the same.

## Exchange and merge handoffs

Export Project content or include valid local drafts through the shared CLI:

```sh
python -B localization/tools/merge_localization.py --export-locale RU_RU --output ru-project-handoff.zip
python -B localization/tools/merge_localization.py --export-english --output en-project-handoff.zip
python -B localization/tools/editor_cli.py export --locale RU_RU --output ru-working-handoff.zip
python -B localization/tools/editor_cli.py export --english --output en-working-handoff.zip
```

Repeat `--locale` for multiple selected languages. Exports contain complete selected-language CSVs and include dependent English for review. Private snapshot/settings/passwords are excluded; incomplete drafts belong in `backup`, not a handoff.

Preview incoming English and translations together:

```sh
python -B localization/tools/merge_localization.py en-handoff.zip ru-handoff.zip
```

For every conflict, repeat `--use-incoming LOCALE:TXT_KEY` or `--keep LOCALE:TXT_KEY`. Review English decisions before dependent translations, then use the same choices for Apply:

```sh
python -B localization/tools/merge_localization.py en-handoff.zip ru-handoff.zip --keep en_US:TXT_KEY_MY_NEW_DESCRIPTION --use-incoming RU_RU:TXT_KEY_MY_NEW_DESCRIPTION
python -B localization/tools/merge_localization.py en-handoff.zip ru-handoff.zip --keep en_US:TXT_KEY_MY_NEW_DESCRIPTION --use-incoming RU_RU:TXT_KEY_MY_NEW_DESCRIPTION --apply
python -B localization/tools/manage.py check
```

Key names are examples; choose rows from your preview. Unresolved replacements stop Apply. Stale/blocked rows must be kept; update/review them against current source separately. A newer timestamp alone does not settle a conflict. `--apply` backs up affected files, rebuilds according to configuration and restores changed inputs on failure. Unrelated rows stay intact. `--project <path>` selects another prepared checkout; `merge_translation_handoff.py` is available for translation-only ZIPs.

Review the final canonical-source and runtime-XML diff rather than replacing an entire team CSV with the exported CSV. Do not merge directly while overlapping browser/CLI project operations are running.

## Application maintenance and reference operations

| Task | Command/service |
| --- | --- |
| Fetch/decrypt/verify a team reference | `snapshot_cloud.py fetch --url "<team direct-download link>"` (prompts for encryption password). |
| Inspect/capture/merge a proposed official-text baseline | `collect_vanilla.py`; review before publishing its fingerprints. |
| Encrypt a reviewed snapshot | `snapshot_cloud.py encrypt`; use `--help` for input/output options. |
| Carry translations from an old project | `sync_lekmod_versions.py --carry-from <old-project>`. |
| Compare release changes | `sync_lekmod_versions.py --since <version>` or `--version <version>`; add `--online` to fetch missing official comparisons. |
| Repair a closed portable editor | `repair_editor.py --editor-root "<application folder>"`. |

Run commands from the destination checkout when carrying/comparing versions. They do not install the mod in Game. Carrying preserves destination edits, reports conflicts and archives unavailable keys; changed English requires translation review. Keep the old project and its local history.

The portable application updater verifies the published ZIP and replaces its known application files while retaining private workspaces. Documentation is linked online from its short README/START file, keeping the package format compatible with existing updaters.

## Reference data and project files

| Path | Role |
| --- | --- |
| `localization/en_US/primary.xml` | Canonical editable English; commit. |
| `localization/translations/*.csv` | Reviewed translations, grammar, notes and formatting approvals; commit. |
| `localization/reference/*.json.gz` | Shared fingerprints, release comparisons and English date index; commit. |
| `LEKMOD/Override/CIV5Units_Mongol.xml` | Generated runtime localization; commit and ship with the mod. |
| `localization/editor/` | Browser UI and application manifest. |
| `localization/tools/` | Shared services, CLI, generators and tests. |
| `localization/config.json` | Strict `On`/`Off` switches with English help for each. |
| `localization/workspace/` | Private snapshots, catalogs, drafts/history/Saves, settings, downloaded projects, reviews, backups and logs; never commit. |

The generator ships reviewed translations for Lekmod additions and modified vanilla text. Missing/stale translations use current English fallback. Unchanged vanilla strings use the game's own localization. Unresolved English source conflicts are withheld for review.

The full official-text snapshot stays outside public Git. Shared hashes let contributors and CI use one baseline without publishing official sentences. Fetch the encrypted team snapshot from an IDE with:

```sh
python -B localization/tools/snapshot_cloud.py fetch --url "<team direct-download link>"
python -B localization/tools/manage.py prepare
```

Fetch prompts for the password and verifies before installation. Maintainers can inspect/capture/merge a proposed baseline with `collect_vanilla.py`, review it, then encrypt with `snapshot_cloud.py encrypt`. Release reviewed fingerprints and the encrypted link together. Do not commit passwords or full official-text snapshots.

## Validation and contributing

`manage.py prepare` runs enabled English synchronization, catalog generation and runtime generation. `manage.py check` runs enabled structural audits, the English-sync check, repository reference inventory, unit tests and deterministic runtime-generation check. `manage.py check --ci` uses shared fingerprints without requiring a private full snapshot.

| Configuration group | Switches |
| --- | --- |
| Build | `english`, `catalog`, `shipped` |
| Checks | `art`, `primary`, `english_sync`, `inventory`, `unit_tests`, `shipped` |

Values must be exactly `On` or `Off`. Disabling a build component does not imply that its output was regenerated. Keep normal checks enabled when preparing a contribution.

GitHub checks run shared audits/tests, browser interaction tests, real Chromium search-layout checks and Windows snapshot tests. The Windows application workflow builds and checks the packaged EXE, Apply/history scenarios, runtime XML, updater restart and recovery. These checks complement an actual game test.

Before submitting a PR:

1. Review canonical English, translation CSVs and gameplay references.
2. Run prepare/check and inspect generated XML.
3. Resolve affected source conflicts, stale translations and unexpected formatting changes; include intentional formatting approvals in the CSV diff for review.
4. Test affected text in a matching game when available; report screens/languages tested.
5. Commit sources and generated runtime XML. Exclude `localization/workspace/` and the full snapshot.

## Maintain manual screenshots

The browser manual uses actual HTML/JavaScript with labelled demonstration responses and non-working example paths/link. Recreate its images in a temporary Node dependency folder:

```sh
npm install --prefix /tmp/lle-manual --no-save playwright@1.56.0
/tmp/lle-manual/node_modules/.bin/playwright install --with-deps chromium
NODE_PATH=/tmp/lle-manual/node_modules node localization/tools/docs/capture_manual.cjs
```

On Windows, choose an equivalent temporary dependency path and set `$env:NODE_PATH` in PowerShell. The script runs only a localhost demonstration server, clicks the actual controls and writes `localization/docs/images/*.png`; it does not connect a real project/game or publish anything. Inspect the resulting images when UI labels/layout change. Do not replace these with screenshots containing private snapshot sentences or passwords.
